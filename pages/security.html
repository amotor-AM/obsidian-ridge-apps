Security policy

Effective 2026-11-09. Applies to Obsidian Ridge Labs apps on the Atlassian Marketplace.

Report a security issue

Email support@obsidianridgelabs.com with "Security" in the subject. Tell us the app, the version or date you tested, the steps to reproduce, and the impact you expect. Please do not test against Atlassian sites you do not own, and give us a reasonable time to fix the issue before you publish it.

We confirm receipt within two business days, keep you updated while we work on it, and credit you in the release notes if you would like.

How we fix issues

We fix security issues within the time frames of Atlassian's Marketplace Security Bug Fix Policy, based on severity. Fixes are released through the Forge platform, so installed sites get them without any action from customers unless a fix needs new permissions.

How our apps are built

  • Our apps run on Atlassian Forge, Atlassian's hosted app platform. Customer data stays on Atlassian's infrastructure unless an app's listing says otherwise.
  • Each app asks for the narrowest permissions it needs. Read-only Gantt Chart for Jira has one, read:jira-work, and cannot change any data. Timesheet Report for Jira has two read scopes, read:jira-work and read:jira-user, and cannot log or change time. Markdown Renderer for Confluence has none; it only renders the text saved in its own macro.
  • None of our apps has a server of its own, stores customer data outside Atlassian and the viewer's browser, or declares external network access.
  • Apps read Jira as the signed-in user, so people only see what Jira already lets them see.
  • Text from Jira and Confluence is escaped or sanitized before it is drawn, raw HTML in Markdown is shown as text, and CSV exports defuse cells that a spreadsheet could read as formulas.
  • We do not ask for or store passwords, API tokens or personal access tokens.
  • Before each release we check our dependencies for known vulnerabilities.
